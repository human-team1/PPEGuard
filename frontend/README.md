# PPE Guard Frontend

PPE Guard 프론트엔드는 PySide6 기반 데스크톱 클라이언트입니다.  
단독으로는 완전 동작하지 않으며, 백엔드 서버가 먼저 실행되어 있어야 합니다.

## 실행 전 확인

- Python `3.10.x` 권장
- 백엔드 서버 실행 필요
- 기본 백엔드 주소: `http://127.0.0.1:5000`

## 설치 방법

```bash
cd frontend
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

패키지 설치:

```bash
pip install -r requirements.txt
```

## 실행 방법

```bash
python main.py
```

실행 후 메인 화면에서 서버 주소를 입력하고 연결 테스트를 진행합니다.

## 백엔드 서버 주소 설정 방법

기본값은 아래 주소입니다.

```text
http://127.0.0.1:5000
```

설정 방법:

1. 프로그램 실행
2. 서버 주소 입력란에 백엔드 주소 입력
3. 연결 테스트 실행
4. 성공 시 웹캠 또는 비디오 분석 시작

## 개발 시 연결 확인 방법

먼저 백엔드에서:

```bash
cd backend
python app.py
```

그 다음 프론트에서:

```bash
cd frontend
python main.py
```

프론트에서 확인할 항목:

- 서버 연결 테스트 성공 여부
- 웹캠 분석 시작 후 세션 생성 여부
- 비디오 업로드 후 결과 조회 여부
- 실시간 프리뷰와 bbox overlay 표시 여부
- 결과 화면에서 세그먼트/사람 결과 조회 여부

## 프론트에서 알아야 할 설정

프론트는 별도 `.env` 기반 설정 파일을 사용하지 않습니다. 현재 실행 시점에 중요한 값은 아래와 같습니다.

### 1. 백엔드 API 주소

- 사용 위치: GUI 서버 주소 입력란
- 기본값: `http://127.0.0.1:5000`
- 영향:
  - 잘못 입력하면 연결 실패
  - 다른 PC 백엔드에 붙을 때는 해당 IP/포트로 변경 필요

### 2. 서버 포트

- 기본 백엔드 포트: `5000`
- 백엔드 `.env`의 `PORT` 또는 `FLASK_RUN_PORT`와 맞아야 합니다.

### 3. 웹캠 사용 여부

- 별도 설정 파일 값은 없고, 입력 선택 화면에서 웹캠 모드를 선택합니다.
- 웹캠 프리뷰가 보이려면:
  - 로컬 카메라 접근 가능
  - 백엔드 Socket.IO 연결 가능
  - 백엔드 웹캠 분석 파이프라인이 정상 동작해야 함

### 4. 업로드 파일 관련 주의사항

- 지원 영상 파일은 백엔드 허용 포맷 기준을 따릅니다.
- 너무 큰 영상은 업로드/분석 시간이 길어질 수 있습니다.
- 분석 속도는 프론트보다 백엔드 `.env` 설정 영향이 큽니다.

## 프론트가 백엔드에 의존하는 부분

아래 항목은 반드시 이해하고 테스트해야 합니다.

- 프론트는 단독으로 완전 동작하지 않습니다.
- 백엔드 서버가 먼저 실행되어 있어야 합니다.
- 백엔드 `.env` 설정에 따라 분석 성능과 응답 속도가 달라집니다.
- 특히 아래 값은 프론트 체감 성능에 직접 영향을 줍니다.
  - `WEBCAM_CAPTURE_FPS`
  - `WEBCAM_ANALYSIS_FPS`
  - `WEBCAM_FRAME_QUEUE_SIZE`
  - `OCR_INTERVAL_SEC`
  - `OCR_WORKER_COUNT`
  - `WEBCAM_MAX_TRACK_OCR_COUNT`
  - `ANALYSIS_FPS`
  - `MAX_CONCURRENT_SEGMENTS`

## 성능 관련 주의사항

- 현재 CPU 병목은 주로 백엔드 OCR 수행 시점에서 발생할 수 있습니다.
- 프론트가 느려 보이는 경우도 실제 원인은 프론트가 아니라 백엔드 OCR/분석 지연인 경우가 많습니다.
- 실시간성을 우선하면 백엔드에서 오래된 프레임을 버리는 쪽이 더 적절합니다.
- 프론트에서 프레임이 늦게 보이거나 bbox가 끊겨 보이면 먼저 백엔드 OCR 설정을 확인하세요.

## 개발/테스트 시 확인 포인트

웹캠 경로:

- 프리뷰 이미지가 표시되는지
- bbox overlay가 갱신되는지
- 분석 시작 후 실시간 이벤트가 오는지
- 분석 종료 시 세션이 정상 정리되는지

비디오 경로:

- 업로드 직후 세션 생성이 되는지
- 진행률이 표시되는지
- 세그먼트 저장 이벤트가 들어오는지
- 결과 화면에서 OCR/PPE 결과가 조회되는지

## 자주 하는 실수

- 백엔드를 실행하지 않고 프론트만 실행
- 서버 주소를 `localhost`와 다른 실제 IP 환경에서 혼용
- 방화벽/포트 차단 상태에서 연결 문제를 프론트 버그로 오해
- 웹캠이 점유 중인데 프론트 문제로 착각
- 프론트 성능 이슈로 보이지만 실제로는 백엔드 OCR CPU 병목인 경우

## 권장 실행 순서

1. 백엔드 가상환경 활성화
2. 백엔드 `.env` 확인
3. 백엔드 서버 실행
4. 프론트 가상환경 활성화
5. 프론트 실행
6. 서버 연결 테스트
7. 웹캠 또는 비디오 분석 테스트
## 로그 확인

- 프론트는 운영 기본값에서 프레임 송수신 로그를 남기지 않습니다.
- 연결 성공/해제, 세션 시작/종료, 세그먼트 저장, 소켓 오류만 기본 로그로 봅니다.
- 상세 추적이 필요하면 프론트 실행 환경변수로 `LOG_LEVEL=DEBUG`를 지정하고 실행합니다.

```bash
LOG_LEVEL=DEBUG python main.py
```
