# PPE Guard Desktop Client - 팀 공유용 사용 매뉴얼

본 문서는 사내망에서 구동되는 PPE Guard 데스크톱 프론트엔드 프로그램(MVP)의 사용자 및 팀원 대상 실행 매뉴얼입니다.

## 1. 실행 및 사용 절차 (User Flow)

1.  **프로그램 실행**: 전달받은 `PPEGuard_Client` 폴더 내의 `PPEGuard_Client.exe` 파일을 더블클릭하여 실행합니다.
2.  **서버 연결**: 앱 실행 후 좌측 상단의 [서버 연결] 패널에 사내망 백엔드 API 주소(예: `http://192.168.0.x:5000`)를 입력하고 **[연결 테스트]** 버튼을 클릭합니다. 
3.  **모드 선택**: 
    *   **동영상 파일**: 로컬 `mp4` 파일을 찾아 지정합니다.
    *   **웹캠**: 즉시 내장 카메라 권한을 획득하여 화면에 실시간 스트리밍을 시작합니다.
4.  **분석 시작**: 하단의 **[분석 시작]** 버튼을 누르면 백엔드로 비동기 세션 생성을 요청하고, 우측 **통합 결과 조회** 탭으로 자동 이동합니다.
5.  **결과 확인**: 좌측의 분석 내역 목록에서 항목을 클릭하면, 우측 뷰어에 헬멧/조끼 착용 판단 상태와 캡처된 스냅샷 이미지가 출력됩니다.

## 2. 배포본 사용 시 주의사항 

- **배포 폴더 통째로 보존**: 사용자에게 배포할 때는 반드시 `dist/PPEGuard_Client/` **폴더 전체를 압축(.zip)하여 전달**해야 합니다. 
- **실행 파일 분리 금지**: 폴더 안의 `PPEGuard_Client.exe` 파일만 밖으로 빼내서 배경화면으로 이동시켜 실행하면 내부 라이브러리(.dll) 참조 오류로 동작하지 않습니다. (바탕화면에 아이콘을 원할 경우 해당 `.exe` 파일의 '바로 가기'를 만드세요.)

## 3. 프론트엔드 구동을 위한 백엔드 응답 규약 (기대 스펙)

이 데스크톱 프로그램이 정상 동작하기 위해서는 현재 백엔드 API가 다음과 같은 응답 규약을 제공해 주기를 기대하고 설계되었습니다.

*   `GET /health`: JSON `{"status": "healthy"}`를 타임아웃(3초) 내에 리턴해 주어야 합니다.
*   `POST /api/v1/sessions`: body에 `source_type`, `source_name`, `frame_interval_sec`를 수신하고, 응답으로 `session_id`와 `status` 필드를 즉시 반환해 주어야 프론트의 분석 대기 UI가 해제됩니다. 단, 비디오 실제 샘플링 간격은 `frame_interval_sec`가 아니라 백엔드 `ANALYSIS_FPS`가 결정하며, `frame_interval_sec`는 호환용 메타데이터로만 유지됩니다.
*   `GET /api/v1/results`: DTO 호환이 가능하도록 분석 완료 목록을 리스트 배열 형태로 제공해야 하며, 프론트에서 재정렬하지 않으므로 백엔드에서 미리 최신순 정렬된 상태로 응답해 주어야 합니다.
*   `GET /api/v1/results/{id}`: 특정 결과의 세부 상태 및 `image_path` (현재는 로컬 마운트 절대/상대경로 참조용) 데이터를 반환해야 합니다.

## 4. MVP 버전의 알려진 제한사항 (Known Limitations)

1.  🚨 **[위험] 비디오 파일 네트워크 전송 미구현**: 현재 분석 시작 시 API 페이로드(`source_name`)에 동영상 파일의 로컬 **경로 문자열**만 전송하는 구조입니다. 이는 MVP 단계에서 백엔드와 프론트가 동일 저장소 볼륨에 접근 가능하다는 전제하에 만든 **임시 방식**입니다. 정식 운영 시에는 대용량 영상 스트림 업로드(Multipart) 아키텍처로 반드시 개편되어야 하며, 이 단순 문자열 전송 방식을 운영 구조로 오해하거나 확정 스펙으로 삼으면 안 됩니다.
2.  **보안 체계 부재**: 사내망 통제 환경(On-premise)을 전제로 제작되어 JWT 인증, HTTPS 보안 프로토콜 계층이 빠져있습니다. 네트워크 포트만 열려있으면 즉시 연결됩니다.
3.  **스트리밍 실시간성 제한**: 현재는 [분석 시작] 버튼 트리거 시 프레임을 넘기는 1회성 스냅샷 호출 중심입니다. 24시간 실시간 무중단 CCTV 모니터링을 위해서는 기반 인프라 확장이 추후 과제로 필요합니다.
